# Communication UI implementation plan

Status: proposed for review. This plan implements the approved visual direction in `docs/communication-ui-prototype.html`; it does not authorize new messaging functionality or a deployment.

## Goal and scope

Replace the Communication hub's side drawer with a full-width workspace and six persistent sections: Overview, Broadcast, Automatic messages, Reminders, Review & delivery, and Workflows & settings. The prototype is an interaction and layout reference; its example counts and sample records must be replaced with actual data. Every existing function must remain usable, including features only represented as placeholders in the prototype.

## Backend decision

The planned redesign is **primarily frontend** in `E:/Allprojects/merasoftware`. Existing backend endpoints, policies, templates, queues and scheduler remain the source of truth. No backend schema, sending behavior, new reminder provider, production configuration, or deployment is planned. Some prototype summaries might not have an existing endpoint with the exact semantics needed: inspect the real response before displaying a count; use an existing accurate value or omit the card rather than inventing or mislabelling one. If a genuinely necessary backend change is discovered, document its specific reason and scope before including it. Do not treat delivery history as a complete business-action log.

## Work stages and expected result

1. **Inventory and baseline.** Inspect the current website and backend working trees, applicable instructions and local Next.js documentation; map each current panel, endpoint, role, action, deep link, loading state and existing tests to its destination. Preserve all uncommitted work. Result: a feature checklist against which the redesign can be checked, including website-only and portal-admin access.
2. **Navigation and layout.** Replace drawer, backdrop, page-scroll lock and drawer-specific focus behavior with responsive full-width content and six tabs. Support keyboard navigation, clear headings, browser Back/Forward, refresh, direct links and old `view`, `panel`, `tab`, `app`, `show` and `event` links. Keep existing authorization checks and show appropriate unavailable states. Result: a shareable workspace without side pop-ups or broken existing links.
3. **Overview.** Connect attention items, recent message activity and accurate existing counts/status to real APIs. Each item opens the right tab and filter. Distinguish unavailable/loading from zero and do not imply a complete activity log. Result: a useful live starting page.
4. **Broadcast.** Present existing audience/group, channel, saved message, subject, content, media, preview and sending controls in the prototype's clear sequence. Keep saved drafts, eligibility and blocked-contact checks, server job state, actual send validation, history, recipient results and supported retry behavior. Do not invent unsupported targeting or channel behavior. Result: an easier broadcast flow with existing delivery semantics.
5. **Automatic messages.** Rework action discovery, application/category/search filters, action details, template selection and management, sending mode and channel into a full-page layout. Retain action-specific allowed modes, variables, editor/preview, Standard and custom templates, conflict handling and existing review behavior. Result: find an action and understand its message and settings together.
6. **Reminders.** Organize rule drafts, activation/stop and preview, new reminder activity, and existing offer/reservation reminders into distinct views. Preserve the monthly renewal and global future-broadcast source limits, supported channels, actual lifecycle and frozen offer agreements. Explain rule revision and scheduler status accurately; retain only supported retries. Result: clearer rules and history without changing when reminders are sent.
7. **Review & delivery.** Give existing email review/outbox/history and WhatsApp queue/history clear subsections with accurate channel, application, status and available actions. Preserve review expiry, Send/Don't Send, channel restrictions and retry safeguards. Put bounded business activity in its own clearly labelled view. Result: the user can find pending decisions and delivery outcomes without suggesting that different records are one complete unified inbox.
8. **Workflows & settings.** Provide full-width destinations for WhatsApp connection, sending rules, Auto Reply, Final Message and Reservations; retain all existing controls, details and applicable portal-admin restrictions. Result: specialised functions remain complete and discoverable.
9. **Drafts, accessibility and verification.** Protect unsaved edits when switching sections or using Back, without interfering with the existing review decision flow. Verify loading, errors, empty states, responsive layouts, focus and keyboard access. Run relevant browser and regression tests, TypeScript/lint and production build sequentially where shared `.next` requires it. Test live-data behavior with isolated fixtures/fake providers; do not send real messages, enable scheduler flags or deploy. Compare every inventoried function and old URL against the completed UI. Result: a working redesign with evidence that existing flows remain intact.

## Important boundaries

- Full-page workspaces replace the hub's side drawer; short confirmation dialogs may remain when they serve a decision, such as discarding unsaved edits. Existing template/review dialogs should be evaluated as part of their full-page flow so they do not recreate the same cramped experience.
- No fabricated prototype records, counts, status, send actions or retry options will appear in the real interface.
- Existing legacy reminder ownership, custom templates, policy choices and admin/customer-origin behavior must be preserved. Configurable reminders currently support monthly renewal and Broadcast only; the latter applies globally to future eligible broadcasts after activation.
- Check existing local changes before editing; do not clean, reset, deploy or send production messages as part of verification.
